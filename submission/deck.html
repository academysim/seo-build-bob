01  Team and project

A team of one, and five live websites

I'm Malikai, owner of Academy Sim Racing, a sim racing lounge in Tampa. I'm not a developer. About five years ago I built our five websites from YouTube guides: lounge, events, builds, driver school and health.

Most of our customers now find us through those sites, so they can't go down while being fixed.

The project: modernize the Python code that builds all five sites, using IBM Bob, without changing anything a visitor sees.

Academy Sim Racing x IBM Bob2

02  The problem

Every fix had to be made five times

  • Five audit scripts, 129 to 194 lines each, each with its own copy of the same checks
  • Four near-identical scripts for linking the sites together
  • Tracking tag, site addresses and phone number typed out in many files
  • 13 hand-written test cases and no test runner
  • 136 shipped files that nothing checked at all
  • One wrong byte can break a booking form, a tracking tag or a search ranking
Academy Sim Racing x IBM Bob3

03  The approach

Build the safety net first

Before any code changed, every file the sites ship got a SHA-256 fingerprint: 263 of them.

Every step after that had to end with the fingerprints matching and the tests passing. Bob worked from a written plan, one phase per commit, with deploy credentials switched off.

The demo proves the net works: one added character in the live homepage is caught, undone, and everything matches again.

06  Learnings and next steps

What we learned, what comes next

Learned

  • Write the safety check before the refactor. It's what made it safe to let an AI agent touch live code.
  • Lock in old behaviour with tests before moving it. "It still runs" isn't proof.
  • Start Bob in the right folder. Twice it ran in the wrong one and built from scratch instead.
  • Check the write-up like the code. One summary called a partial refactor done; we corrected it.

Next

  • Move the remaining 42 older scripts onto paths.py
  • Bring the deploy tools under tests against a staging site
  • Make the fingerprint check a required step before every deploy
  • Run the live-site audit on a schedule
